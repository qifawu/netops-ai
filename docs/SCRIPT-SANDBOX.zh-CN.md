# 巡检两层分析与「AI 写脚本」的安全边界

代码入口见文末「文件清单」。

## 1. 两层结构

| 层 | 适用 | 做法 | 是否落地 |
|---|---|---|---|
| 通用类 | 同类结果反复出现、或判断能写成确定性规则（逐条对表、阈值、计数） | 固定分析：现成模板 / 通用规则（含表对表）优先；表达不了再由助手写脚本，审核后定时复用 | 脚本入库，带版本 |
| 特殊类 | 一次性、每次都不一样、需要结合上下文推理 | AI 智能分析，实时推理 | 结论只进本次报告，**不生成可复用脚本** |

分流规则由 `layer_router.decide` 实现，按以下顺序判断：

1. 脚本库里已有同类的已批准脚本 → 直接复用；
2. 现成模板 / 通用规则能表达 → 用模板，不写脚本、不调 AI；
3. 需求能写成确定性规则，或同一类结果在 30 天窗口内重复 ≥ N 次（默认 N = 3）→ 沉淀脚本，进待审；
4. 其余 → AI 智能分析。

「同一类」用类别指纹表示：`fingerprint(命令, 判断类别)`，命令小写并折叠空白。阈值 N 与窗口可调。

模板优先于脚本，是因为模板已经过审核、没有执行面，最便宜也最可审计；脚本是模板表达不了时的补充。

## 2. 安全边界（逐条对应评审建议）

威胁模型：要防的是「助手写出的脚本出事」（写错、被样本里的内容诱导、越权），不是对抗一个有本机权限的恶意人。
能批准脚本的人必须是维护者 / 管理员。

### a. 只读
脚本只拿到一个字典 `ctx`：本次输出、上一次输出、设备名、参数。命令由系统过只读白名单执行，脚本不能执行命令。
脚本拿不到环境变量、凭证、其它文件；执行子进程的环境变量清空，工作目录是一个空的临时目录。
**采纳。**

### b. 沙箱执行
- 源码先过 AST 白名单：只准 `re / json / csv / ipaddress / collections / datetime / statistics / math / itertools`；
  禁 `open / eval / exec / compile / __import__ / getattr` 等名字，禁双下划线属性，禁 `.format / .format_map`（格式串属性遍历能绕过属性检查）。
- 独立 `python -I` 子进程；超时 5 秒；输出和结论条数有上限；内存上限 256 MB
  （Windows 用 Job Object，POSIX 用 `RLIMIT_AS`）；运行时再加一层受限 builtins 和受限 import。
- **相对建议的调整**：建议里的「无网络」在 Windows 上没有轻量的系统级办法（没有网络命名空间）。
  现在靠三层间接保证——socket 等模块不在白名单、静态检查拦 import、运行时 import 守卫。这是纵深防御，**不是系统级隔离**。
  需要对不可信用户开放时，应放进容器 / 低权限账号，或用 `--network none` 之类的外壳；这一项已列入「已知限制」。
- 「临时只读工作目录」：工作目录是空目录，脚本没有 `open`，读写都做不到，效果等价。

### c. 产物是结构化结论
返回值固定 schema：`status ∈ {pass, fail, baseline}`、`summary`、`metrics`（数字）、`findings`（≤ 20 条）；不合规直接报错。
脚本没有任何通道触发设备变更或告警外发；它的结论只是这条检查的判定，之后走现有检查 → 告警流程，与模板规则完全一样。
**采纳。**

### d. 人工审核后入库
脚本库 `script_registry`：每个脚本有 id 和多个版本，每版一个 JSON，记录源码、sha256、**生成它的需求原文**、模型、自测摘要、
状态流转历史、批准人 / 批准时间、HMAC 签名。
- `pending → approved → revoked`，或 `pending → rejected`；
- 批准要求：静态检查通过、自测通过（含模型按需求给出的用例，至少一条期望报警）、源码哈希对得上、有批准人；
- 取用时再次校验「状态 + 哈希 + 签名 + 静态检查」，任何一项不过就当没批准（文件被手工改过也一样）；
- 改源码 = 新版本，回到待审；旧的已批准版本继续有效，直到新版本批准并撤销旧版本；
- 签名密钥只在本机（`~/.netops-ai/script-signing-key`），拿到 YAML / JSON 文件的人没有它，改了内容也签不出有效签名。
**采纳，并补了版本、撤销、签名。**

### e. 数据脱敏后再给 AI
- 发给模型的样本：口令、团体字、密钥所在行先脱敏（关键词后面的整截换成 `<REDACTED>`，换行保留）；
- 输出可能带口令的命令（`running-config`、`snmp-agent community`、`local-user` 等）**不给模型写脚本**；
- 自测也用脱敏后的同一份样本。
**部分采纳**：当前只脱敏凭证类。IP / 主机名不默认替换，因为脚本要按真实格式解析；若要进一步匿名化，
需要做「稳定映射」（同一个 IP 始终换成同一个占位），列入后续。

### f. 分流规则
见第 1 节。重复计数保存在脚本库目录的 `occurrences.json`。

## 3. 已知限制（如实记录）

1. 不是系统级隔离（见 b）。对不可信用户开放前，需要容器 / 低权限账号。
2. 看板默认没有登录；谁能打开页面，谁就能批准脚本。批准权限要靠登录 / 反向代理 / 网络隔离管住。
   批准人目前取请求里的 `approver`，缺省为 `dashboard`；接入登录用户名是下一步。
3. Job Object 设置失败时（极少见）退回静态检查 + 超时。
4. 签名密钥丢失 / 换机器后，已批准的脚本需要重新批准（这是安全的失败方向）。
5. 「重复 ≥ N 次」的计数目前只提供接口（`record / count`），还没有挂到每次巡检结果上，需要后续接入。

## 4. 开关与配置

- 助手自己写脚本的总开关：环境变量 `NETOPS_SCRIPT_AUTHORING=1`（默认关）。关闭时提示词里没有脚本规则，模型给出的脚本请求也被忽略。
- 脚本库目录：`NETOPS_SCRIPT_LIB_DIR`（默认 `records/check-scripts/`）；签名密钥文件：`NETOPS_SCRIPT_KEY_FILE`。
- 测试一律把脚本库和密钥指向临时目录，不污染真实 `records/`。
